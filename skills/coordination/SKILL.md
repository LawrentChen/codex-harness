# 总控面

## 明确启用

自然人用户可以在承接工作的任意对话中说「这项工作使用总控面」或「使用 _control 接手这个工作」。同一工作启用一次后持续有效，直到工作结束或自然人用户停止使用。无需另回总控任务发指令。

- 新的独立对话需要明确接手总控面工作；已有卡片、跨项目改动、长任务、使用 sub-agent 都不单独构成启用。
- 「查看进度」只查看；「登记待办」只登记，不自动开始实施。讨论、审阅或修改本 skill 本身不启用业务工作跟踪。
- 未启用时，不主动读取、创建或修改总控面账本。普通工作可按需维护项目 `docs/TODO.md`。
- 启用总控面与调用 sub-agent 分别依据自然人用户的要求，不互相推导授权。

## 位置与角色

固定账本根目录为 `~/code/_control/`，按当前自然人用户的主目录解析；不在项目或 worktree 内复制账本。

| 称呼 | 实际含义 |
| --- | --- |
| 自然人用户 | 提出目标、选择优先级和关键取舍的人 |
| 工作任务 / owner | 当前承接工作项的独立对话，通常用任务链接标识 |
| 协调任务 | 承担范围、接口取舍和集成验收的对话，可兼任工作任务 |
| 审查任务 | 按需使用的独立对话或短期 sub-agent |
| 进度总览 | 脚本从卡片生成的视图，无需单独的 AI 维护者 |

单仓工作优先在该仓库或功能 worktree 开始；已知跨仓或归属不明的工作可在 `~/code/` 开始；纯协调可在账本目录开始。对话中途涉及 B/C 仓库时，说明必要范围、读取对应规则并核实环境和 Git 状态后，按既有授权继续。目录与侧边栏归属不改变任务范围或沙箱权限。

## 接手与更新

1. 自然人用户给出卡片路径或 ID 时先读该卡。否则从相关项目总览定位，跨项目再看全局总览；只展开当前卡、直接依赖和必要契约，不通读全部账本。
2. 新建或交接时读取 [任务卡协议](references/ledger.md)。需要跟踪的独立结果各有一张卡，同一工作换对话不重复建卡。
3. 卡片由当前工作任务更新。开始执行、范围或接口变化、出现或解除阻塞、阶段完成和交接时更新；每次工具调用不需要记日志。
4. 更新顶部结构化字段和简短接手摘要，保留决定理由、验证证据和下一步。区分建议、已确认、已实现与已验证。
5. 用 `apply_patch` 创建、修改、删除或移动卡片；hook 自动刷新全局及项目 `OVERVIEW.md`，成功时静默。其他写入方式之后显式执行刷新脚本。
6. 总览是生成文件，不人工编辑；没有新内容时脚本不重写。查看时如需核实新鲜度，可显式刷新后阅读。总览反映卡片记录，不证明任务在线或已经通过验收。

刷新入口：

```bash
/opt/miniconda3/bin/python ~/.codex/skills/coordination/scripts/refresh_overview.py
```

脚本及 hook 的行为、故障处理见 [汇总脚本](scripts/refresh_overview.py) 和 [hook 入口](../../hooks/coordination_after_edit.py)，只有维护它们时才需读实现。

## 跨任务与并行

- 同一结果扩展到其他仓库：保留卡片 ID 和路径，更新 `repos`、范围和验收，脚本会把它纳入相关项目视图。能独立验收的新结果再拆子卡，以 `parent` 和 `depends_on` 关联。
- 共享接口记录唯一正式依据及采用版本。协调任务负责必要的取舍和最终集成；子卡全部完成不自动将父卡标为完成。
- 默认一个工作副本一个写入者。同仓独立 worktree 并行时明确各自范围、接口版本和集成任务；共享资源另行协调，遵守更具体的项目规则。
- 短期 sub-agent 返回结果，由父任务维护卡片；审查任务默认只读。交接卡片写入权时原工作任务先停止写入，再更新 owner。
- 沿用自然人用户已经明确的授权，交接只保留必要的范围、条件和依据。接口兼容与必要验证不因是否启用总控面而改变。
- `CURRENT.md` 仅在需要时记录重点、范围和约定，由相关协调任务维护；不复制子卡状态。控制仓库的 Git 操作如有需要，由一个任务串行执行。

## 工具与边界

- 创建、读取或协调 Codex 任务时检查本次实际可用工具。缺少创建或发送入口时，给自然人用户准备卡片路径和简短接手语，如实说明尚未创建或通知。
- hook 只刷新文件，不唤醒对话。执行依赖前核对相关卡片和接口版本；重大接口变化待依赖方确认采用，不推断运行中的任务已收到通知。
- 卡片是工作状态来源。格式校验失败时保留原总览；刷新报错时说明总览可能未同步，修复后再次刷新，不为凑总览而改成虚假状态。
- 账本不可写时明确报告未同步，继续不依赖它的工作；不在 worktree 新建替代账本。未启用时的待办留在项目 TODO；启用后同一事项可将 TODO 改为指向卡片的链接。
